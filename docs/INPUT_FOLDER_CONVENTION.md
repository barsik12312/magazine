# Конвенция входной папки

Этот документ описывает, как ты собираешь папку с исходниками для задания, и как `scripts/build_task.py` её разбирает в готовый пакет под Nano Banana Pro.

## Идея

Ты не подписываешь файлы вручную каждый раз. Ты просто кладёшь файлы в папку с очевидными именами, скрипт сам разбирает что есть что и собирает чистый пакет на выход.

- Цифры в начале имени = принты (графические ассеты)
- Слова `спереди / сзади / бирка / фон / модель` = категории исходников
- Текстовый файл `задание` = ТЗ
- Результаты ты не подписываешь — кладёшь в `outputs/` как есть

## Категории и правила сопоставления

| Категория | Что это | Имена файлов (case-insensitive) |
|---|---|---|
| Принт 1 (front) | графика на грудь | `1.*`, `1_*.*`, `print_1.*`, `print-front.*`, `front_print.*` |
| Принт 2 (back) | графика на спину | `2.*`, `2_*.*`, `print_2.*`, `print-back.*`, `back_print.*` |
| Принт 3 (tag) | графика бирки | `3.*`, `3_*.*`, `print_3.*`, `print-tag.*`, `tag_print.*` |
| Спереди | реальное фото футболки спереди | `спереди*`, `front*`, `garment-front.*` |
| Сзади | реальное фото футболки сзади | `сзади*`, `back*`, `garment-back.*` |
| Бирка | реальное фото бирки | `бирка*`, `tag*`, `label*`, `garment-tag.*` |
| Фон | альтернативный фон, заменяет балкон | `фон*`, `background*`, `bg*`, `scene*` |
| Модель | референс позы / типажа модели | `модель*`, `model*` |
| Задание | текст задания | `задание.*`, `brief.*`, `task.*` (только `.txt` / `.md`) |

Если файл не подошёл ни под что — он копируется в `extras/` без переименования и в промптах не используется.

Если для одной категории совпало несколько файлов — берётся первый по сортировке имён, остальные складываются в `extras/`.

## Дефолты

- **Фон**: если в папке нет файлов с именами `фон*`, `background*`, `bg*`, `scene*` — для футболок автоматически подмешиваются balcony references из `stores/tshirts/backgrounds/balcony_template/`.
- **Принт 3 / бирка**: если нет реальных фото и графики — генерируется только базовый промпт бирки.
- **Модель**: если нет — модель описывается дефолтно как «young man early 20s, slim athletic, dark hair».

## Пример входной папки

```
inputs/2026-05-04_givenchy/
├── задание.md
├── 1.png                        ← front print
├── 2.jpg                        ← back print (sufrboard / CC)
├── 3.png                        ← опц., графика бирки
├── спереди.jpg                  ← фото футболки спереди
├── сзади.jpg                    ← фото футболки сзади
├── бирка.jpg                    ← фото бирки
├── модель.jpg                   ← референс модели
└── (фон отсутствует → дефолт = балкон)
```

## Что получится на выходе

```
stores/tshirts/tasks/2026-05-04_givenchy/
├── 00_BRIEF.md                       ← брифинг (включая текст задания)
├── inputs_snapshot/                  ← точная копия исходников (для истории)
├── outputs/                          ← сюда сохраняешь финальные картинки
└── READY_FOR_GEMINI/
    ├── README.txt
    ├── KNOWN_ISSUES.txt
    ├── 01_PROMPT_FRONT.txt           ← футболка спереди
    ├── 02_PROMPT_BACK.txt            ← футболка сзади
    ├── 03_PROMPT_TAG.txt             ← бирка
    ├── 04_PROMPT_MODEL_FRONT.txt     ← человек спереди (ссылается на твой результат шага 1)
    ├── 05_PROMPT_MODEL_BACK.txt      ← человек сзади (ссылается на твой результат шага 2)
    └── refs/
        ├── print_1_front.png
        ├── print_2_back.jpg
        ├── print_3_tag.png           ← опц.
        ├── garment_front.jpg
        ├── garment_back.jpg
        ├── garment_tag.jpg
        ├── scene_01.jpg              ← либо балкон, либо твой кастомный фон
        ├── scene_02.jpg
        ├── ...
        └── model_01.jpg              ← опц.
```

## Что такое «бирка»

«Бирка» в этой системе — это **маленький второй принт на лицевой стороне футболки прямо под горловиной** (как маленький брендовый логотип под воротничком на стрит-вир футболках). НЕ внутренняя пришитая нашивка с тыла.

- Спереди она видна (вместе с основным грудным принтом)
- Сзади её не видно
- Это просто принт меньшего размера, в той же технике, что и основной
- **Бирка опциональна:** если в задании нет принта `3` (`print_3_tag`), шаг 03 пропускается, а на шагах 01/04 бирка не наносится

## Логика 5 промптов (edit-mode за один прогон)

Главное: для шагов 01/02/03 мы **не генерим сцену с нуля**. Мы делаем edit поверх твоего реального фото футболки. За один прогон стираем старые принты и наносим новые.

1. **01_PROMPT_FRONT** — edit поверх `garment_front`:
   - стирается старый основной грудной принт
   - стирается старый маленький принт под горловиной (бирка), если он там был
   - наносится `print_1_front` на грудь (большой)
   - наносится `print_3_tag` под горловину на лицевой стороне (маленький) — если он есть; если нет, под горловиной остаётся чистая ткань
   - всё остальное в кадре (фон, поза, ткань, свет) — без изменений
2. **02_PROMPT_BACK** — edit поверх `garment_back`:
   - стирается старый back-принт
   - наносится `print_2_back` на спину
   - бирка/коллар-принт со спины не виден, ничего там не дорисовывается
3. **03_PROMPT_TAG** — близкий кадр маленького принта-бирки на лицевой стороне под горловиной с новым `print_3_tag`. **Этот шаг создаётся ТОЛЬКО если в задании есть `print_3_tag`.** База = `garment_front`.
4. **04_PROMPT_MODEL_FRONT** — человек спереди. **Главный source of truth — твой готовый результат шага 1** (там уже грудной принт + бирка, если она была). Плюс `print_1_front` и `model_*`.
5. **05_PROMPT_MODEL_BACK** — человек сзади. **Главный source of truth — твой готовый результат шага 2** (бирка не видна, только back-принт). Плюс `print_2_back` и `model_*`.

Кадры с человеком всегда строятся ПОСЛЕ кадров продукта, на их основе.

## Роль балкона / scene_*

Балкон-референсы (`scene_*`) — это **detail-memory**, а не scene-donor. Они дают модели чистую визуальную память о том, как выглядит окружение. Они НЕ заменяют сцену из `garment_front` / `garment_back`. Сцена остаётся та, что на исходном фото; `scene_*` подключаются, только если модели нужно «восстановить» крошечные пиксели фона, оказавшиеся под старым принтом.

Если ты хочешь сменить балкон на другой фон — клади его в папку как `фон*` / `background*` / `scene*`, и тогда уже на этапе генерации можно будет попросить модель пересобрать сцену по нему. Но базовый pipeline футболочного задания — это **edit поверх garment_front/back**, без замены сцены.

## Как пользоваться

```bash
python scripts/build_task.py \
  --type tshirt \
  --slug givenchy-v3 \
  --input inputs/2026-05-04_givenchy/
```

Скрипт прочитает входную папку, разложит файлы по категориям, нормализует имена и соберёт `READY_FOR_GEMINI/`.

Для подкатегорий (бельё, одежда) конвенция та же, но другие промпты — описаны в их отдельных шаблонах.
