# Конвенция входной папки

Этот документ описывает, как ты собираешь папку с исходниками для задания, и как `scripts/build_task.py` её разбирает в готовый пакет под Nano Banana Pro.

## Идея

Ты не подписываешь файлы вручную каждый раз. Ты просто кладёшь файлы в папку с очевидными именами, скрипт сам разбирает что есть что и собирает чистый пакет на выход.

- Цифры в начале имени = принты (графические ассеты)
- Слова `спереди / сзади / бирка / фон / модель / голова` = категории исходников
- Текстовый файл `задание` = ТЗ
- Результаты ты не подписываешь — кладёшь в `outputs/` как есть

## Категории и правила сопоставления

| Категория | Что это | Имена файлов (case-insensitive) |
|---|---|---|
| Принт 1 (front) | графика на грудь | `1.*`, `1_*.*`, `print_1.*`, `print-front.*`, `front_print.*` |
| Принт 2 (back) | графика на спину | `2.*`, `2_*.*`, `print_2.*`, `print-back.*`, `back_print.*` |
| Принт 3 (tag) | графика бирки (внутренней горловины) | `3.*`, `3_*.*`, `print_3.*`, `print-tag.*`, `tag_print.*` |
| Спереди | реальное фото футболки спереди | `спереди*`, `front*`, `garment-front.*` |
| Сзади | реальное фото футболки сзади | `сзади*`, `back*`, `garment-back.*` |
| Бирка (фото) | реальное фото бирки (горловина крупно) | `бирка*`, `tag*`, `label*`, `garment-tag.*` |
| Человек спереди | фото модели во весь рост спереди | `чспереди*`, `model_front*`, `model-front*` |
| Человек сзади | фото модели во весь рост сзади | `чсзади*`, `model_back*`, `model-back*` |
| Голова спереди | лицо / голова модели — identity-lock | `голова_спереди*`, `head_front*`, `head-front*`, `face*` |
| Голова сзади | затылок / волосы — identity-lock | `голова_сзади*`, `head_back*`, `head-back*` |
| Design sketch | B&W коллаж front+back от дизайнера (design-intent reference, **не принт**) | `коллаж*`, `эскиз*`, `зарисовк*`, `sketch*`, `mockup*`, `design*` |
| Фон | альтернативный фон, заменяет балкон | `фон*`, `background*`, `bg*`, `scene*` |
| Модель | общий референс позы / типажа модели | `модель*`, `model*` (если без направления front/back) |
| Задание | текст задания | `задание.*`, `brief.*`, `task.*` (только `.txt` / `.md`) |

**Приоритет классификации:** `голова/head/face` → `чспереди/чсзади/model_front/model_back` → `коллаж/эскиз/sketch/mockup/design` → `спереди/сзади/front/back (garment)` → `бирка/tag` → `фон/scene` → `модель/model` → `extras`.

Если файл не подошёл ни под что — он копируется в `extras/` без переименования и в промптах не используется.

Если для одной категории совпало несколько файлов — берётся первый по сортировке имён, остальные складываются в `extras/`.

## Дефолты

- **Фон**: если в папке нет файлов с именами `фон*`, `background*`, `bg*`, `scene*` — для футболок автоматически подмешиваются balcony references из `stores/tshirts/backgrounds/balcony_template/`.
- **Принт 3 / бирка**: если нет графики — шаг 03 пропускается, бирка не наносится.
- **Модель**: если нет — модель описывается дефолтно как «young man early 20s, slim athletic, dark hair».
- **Голова**: если нет `model_head_front` / `model_head_back` — лицо модели не лочится (Gemini генерит случайное).
- **Design sketch**: если есть — попадает в refs как `design_sketch.*` и подключается к шагам 01/02 как **OPTIONAL design-intent reference**. Gemini **не имеет права** извлекать из него графику или применять как принт. Реальные принты — только в `print_1_front.* / print_2_back.* / print_3_tag.*`. На эскизе бирки никогда нет — это никак не отменяет правила про бирку.

## Пример входной папки

```
inputs/2026-05-04_givenchy/
├── задание.md
├── 1.png                        ← front print
├── 2.jpg                        ← back print (surfboard / CC)
├── 3.png                        ← опц., графика бирки
├── спереди.jpg                  ← фото футболки спереди
├── сзади.jpg                    ← фото футболки сзади
├── бирка.jpg                    ← фото бирки (крупный план горловины)
├── чспереди.jpg                 ← фото модели спереди (full body)
├── чсзади.jpg                   ← фото модели сзади (full body)
├── голова_спереди.jpg            ← лицо модели — identity lock
├── голова_сзади.jpg              ← затылок модели — identity lock
├── коллаж.jpg                    ← опц., B&W эскиз front+back от дизайнера (НЕ принт!)
├── модель.jpg                   ← общий референс модели (опц.)
└── (фон отсутствует → дефолт = балкон)
```

## Что получится на выходе

```
stores/tshirts/tasks/2026-05-04_givenchy/
├── 00_BRIEF.md                       ← брифинг (включая текст задания)
├── inputs_snapshot/                  ← точная копия исходников (для истории)
├── outputs/                          ← сюда сохраняешь финальные картинки
└── READY_FOR_GEMINI/
    ├── README.txt
    ├── KNOWN_ISSUES.txt
    ├── 01_PROMPT_FRONT.txt           ← футболка спереди
    ├── 02_PROMPT_BACK.txt            ← футболка сзади
    ├── 03_PROMPT_TAG.txt             ← бирка макро (только если есть `3`)
    ├── 04_PROMPT_MODEL_FRONT.txt     ← человек спереди (ссылается на твой результат шага 1)
    ├── 05_PROMPT_MODEL_BACK.txt      ← человек сзади (ссылается на твой результат шага 2)
    └── refs/
        ├── print_1_front.png
        ├── print_2_back.jpg
        ├── print_3_tag.png           ← опц.
        ├── garment_front.jpg
        ├── garment_back.jpg
        ├── garment_tag.jpg
        ├── model_front.jpg           ← опц.
        ├── model_back.jpg            ← опц.
        ├── model_head_front.jpg      ← опц. (identity-lock лицо)
        ├── model_head_back.jpg       ← опц. (identity-lock затылок)
        ├── design_sketch.jpg         ← опц. (B&W коллаж от дизайнера, design-intent only)
        ├── scene_01.jpg              ← либо балкон, либо твой кастомный фон
        ├── scene_02.jpg
        ├── ...
        └── model_01.jpg              ← опц. (общий модель-референс)
```

**Плюс:** все refs автоматически копируются в `~/Downloads` (или `~/Загрузки`) с префиксом slug и текущим mtime, чтобы они были наверху в файлдиалогах при загрузке в Gemini. Отключается флагом `--no-downloads`.

## Что такое «бирка»

«Бирка» в этой системе — это **маленький печатный брендовый label на ВНУТРЕННЕЙ (изнаночной) стороне ЗАДНЕЙ части горловины** футболки. Это типичное место брендовой этикетки, только не сшитая woven-нашивка, а принт (нанесён ink-ом). На внешней стороне футболки её нет.

**Матрица видимости:**

| Ракурс | Видна ли бирка? | Почему |
|---|---|---|
| Вешалка спереди (шаг 01) | **ДА** | через вырез горловины видно изнанку задней части шеи |
| Вешалка сзади (шаг 02) | **НЕТ** | это внутренняя сторона; снаружи спина чистая |
| Макро бирки (шаг 03) | **ДА** | это и есть её крупный план |
| Модель спереди (шаг 04) | **НЕТ** | шея модели перекрывает горловину |
| Модель сзади (шаг 05) | **НЕТ** | внутренняя сторона + волосы/шея |

**Бирка опциональна:** если в задании нет принта `3` (`print_3_tag`), шаг 03 пропускается, а на шаге 01 бирка не наносится.

## Логика 5 промптов (edit-mode за один прогон)

Главное: для шагов 01/02/03 мы **не генерим сцену с нуля**. Мы делаем edit поверх твоего реального фото футболки. За один прогон стираем старые принты и наносим новые.

1. **01_PROMPT_FRONT** — edit поверх `garment_front`:
   - стирается старый основной грудной принт
   - стирается старый принт бирки на внутренней стороне горловины (если он был виден через вырез)
   - наносится `print_1_front` на грудь (большой)
   - наносится `print_3_tag` на **внутреннюю сторону задней горловины** (видимую через вырез) — если есть; если нет, внутренняя часть горловины остаётся чистой
   - всё остальное в кадре (фон, поза, ткань, свет) — без изменений
2. **02_PROMPT_BACK** — edit поверх `garment_back`:
   - стирается старый back-принт
   - наносится `print_2_back` на спину
   - бирка сзади не видна (она на внутренней стороне), ничего там не дорисовывается
3. **03_PROMPT_TAG** — близкий кадр бирки на внутренней стороне горловины с новым `print_3_tag`. **Этот шаг создаётся ТОЛЬКО если в задании есть `print_3_tag`.** База = `garment_front` (или `garment_tag`).
4. **04_PROMPT_MODEL_FRONT** — человек спереди. **Главный source of truth — твой готовый результат шага 1** (там уже грудной принт; бирка не видна, шея перекрывает). Плюс `model_head_front` (identity-lock) и `model_front` (поза).
5. **05_PROMPT_MODEL_BACK** — человек сзади. **Главный source of truth — твой готовый результат шага 2** (бирка не видна). Плюс `model_head_back` (identity-lock) и `model_back` (поза).

Кадры с человеком всегда строятся ПОСЛЕ кадров продукта, на их основе.

## Роль балкона / scene_*

Балкон-референсы (`scene_*`) — это **detail-memory**, а не scene-donor. Они дают модели чистую визуальную память о том, как выглядит окружение. Они НЕ заменяют сцену из `garment_front` / `garment_back`. Сцена остаётся та, что на исходном фото; `scene_*` подключаются, только если модели нужно «восстановить» крошечные пиксели фона, оказавшиеся под старым принтом.

Если ты хочешь сменить балкон на другой фон — клади его в папку как `фон*` / `background*` / `scene*`, и тогда уже на этапе генерации можно будет попросить модель пересобрать сцену по нему. Но базовый pipeline футболочного задания — это **edit поверх garment_front/back**, без замены сцены.

## Как пользоваться

```bash
python scripts/build_task.py \
  --type tshirt \
  --slug givenchy-v3 \
  --input inputs/2026-05-04_givenchy/
```

Скрипт прочитает входную папку, разложит файлы по категориям, нормализует имена и соберёт `READY_FOR_GEMINI/`. Все refs автоматически скопируются в `~/Downloads` с префиксом `givenchy-v3__`.

Чтобы отключить копирование в Downloads:

```bash
python scripts/build_task.py ... --no-downloads
```

Для подкатегорий (бельё, одежда) конвенция та же, но другие промпты — описаны в их отдельных шаблонах.
